## 판정 규칙

### 비교 모집단은 시·도

시·군·구가 아닙니다. 시·군·구로 쪼개면 관내 주유소가 두세 곳뿐인 곳이 생겨
"관내 1위"가 아무 의미도 없어집니다. 시·도는 가장 작은 세종도 60곳이 넘습니다.

비교 지역은 명단 주소가 아니라 **오피넷이 말하는 현재 소재지**를 씁니다.
명단은 행정구역 개편을 못 따라갑니다 — 인천 서구는 검단구·서해구로 분구됐는데
명단은 아직 `서구`입니다.

### 신호등

```
🟢 가격기준 적합   그 시·도에서 상위 N위 이내
🟡 가격기준 근접   N위 밖이지만 2N위 이내
🔴 가격기준 초과   그보다 뒤
⚫ 과거 미신고     하루라도 가격을 거른 이력이 있음
⚪ 가격정보 없음   오늘 가격이 없어 판정 불가
```

`N` — **서울·경기 10위, 그 밖의 시·도 5위.** 서울(383곳)·경기(2,100여 곳)는
주유소가 압도적으로 많아 같은 5위 기준을 쓰면 사실상 아무도 통과하지 못합니다.
관리 화면에서 바꿀 수 있습니다.

### 순위는 조밀 순위

**1위가 세 곳 동점이면 다음은 4위가 아니라 2위입니다.** 같은 가격이면 같은
등수이고, 등수는 서로 다른 가격의 개수만큼만 존재합니다.

```
값     3,588  3,600  3,602  3,608  3,617 ×8  3,624 ×2  3,626
순위     1      2      3      4      5 ×8       6 ×2      7
```

커트라인도 같은 잣대입니다 — **N번째로 싼 가격**이지 배열의 N번째 값이
아닙니다. 동점이 많은 시·도일수록 커트라인이 뒤로 밀립니다.

### 계수 — 1이 합격선

그 시·도의 상위권 커트라인을 **1**로 두고 비례 환산합니다.

```
계수 ≤ 1   →  적합
계수  > 1   →  기준 초과
```

소수 **넷째 자리**까지 씁니다. 셋째 자리로는 1원 차이가 안 보입니다 — 합산
커트라인이 3,600원 언저리라 1원이 0.00028 이고, 3,608원과 3,609원이 둘 다
`1.002`로 찍혔습니다. 넷째 자리면 `1.0022` · `1.0025`로 갈립니다.

커트라인보다 1원 비싼 곳이 반올림으로 `1.0000`이 되지 않도록 막아 뒀습니다.
1은 합격선이라는 뜻이라 커트라인 이하일 때만 나와야 합니다.

### 기준 셋 — 통합 / 휘발유 / 경유

화면 우상단에서 전환합니다. 셋 모두 집계 단계에서 미리 계산해 싣습니다 —
화면에서 바꿀 때마다 전국 1만 건 분포를 다시 세울 수는 없습니다.

| 기준 | 값 | 모집단 |
|---|---|---|
| 통합 | 휘발유 + 경유 합계 | 두 유종을 **모두** 파는 주유소 |
| 휘발유 | 휘발유 가격만 | 휘발유를 파는 주유소 |
| 경유 | 경유 가격만 | 경유를 파는 주유소 |

모집단 크기가 기준마다 다릅니다(강원: 합산 600 / 휘발유 600 / 경유 602).
한 유종만 파는 곳이 있어서입니다.

**고급휘발유·실내등유는 다루지 않습니다.** 취급하지 않는 주유소가 대부분이라
판정이 '없음'으로 가득 차고, 제도의 관심 대상도 아닙니다.

## 화면

### 지도

전국 시·도 → 시·군·구 → 일반구 → **상세**, 네 단계로 내려갑니다.

- 지역마다 **이름 · 신호등 개수 · 비율 바**(빨·노·초 좌→우, 개수 비율만큼).
- 착한주유소가 없는 지역은 그리지 않고 상위 행정구역 외곽선만 옅게 남깁니다.
- 전국 보기만 기본 1.5배. 시·도로 들어가면 1배로 돌아옵니다 — 시·군·구 단계는
  투영이 이미 그 시·도에 맞춰져 있어 더 키우면 가장자리 군이 잘려 나갑니다.
- **상세 단계에서만** 실제 지도 타일 위에 주유기 아이콘 핀. 전국에 472개를
  찍으면 알아볼 수 없습니다.

배지 위치는 무게중심이 아니라 **최대내접원 중심**에서 잡습니다. 경기도는 서울을
둘러싸고 있어 무게중심이 서울 위에 얹힙니다. 핀 이름표는 아이콘 둘레의 후보
자리 중 다른 이름표와 모든 아이콘을 피하는 곳에 앉힙니다.

### 목록

- 열 머리를 눌러 정렬(오름 → 내림 → 해제). 값이 없는 행은 어느 방향이든 끝으로.
- 상호에 폴 코드가 붙습니다 — `대경주유소(HD)`.
- 휘발유·경유 가격 옆 괄호는 **그 유종만 놓고 본** 시·도 순위입니다.
- `기준 충족(일)` — 8월 1일부터 오늘까지 적합 / 근접 / 초과였던 날 수.
- 요약 띠의 다섯 칸을 누르면 그 판정만 걸러 봅니다.
- **CSV 내려받기** — 보이는 순서 그대로, 세 기준의 순위·계수를 모두 담습니다.

### 판매가 추이

상호나 주유기 아이콘을 누르면 열립니다. 왼쪽에 그래프 둘, 오른쪽에 날짜별
기록표입니다.

그래프를 나눈 이유는 단위가 달라서입니다. 판매가는 1,700~2,000 대이고 계수는
0.94~1.15 라 한 그림에 이중축으로 얹으면 두 눈금을 번갈아 읽어야 합니다.
두 그래프는 같은 x 눈금을 써서 세로로 포개지므로 날짜 라벨은 아래에만 붙입니다.

- 기본 구간은 **8월 1일 ~ 최신일**이고 끝은 매일 밀립니다.
- 아직 안 받아온 구간에서는 선을 끊습니다. 직선으로 이으면 그동안 가격이
  그대로였던 것처럼 보입니다.
- 기록표는 최신 날짜가 위로. 값이 없는 날은 건너뛰지 않고 `정보없음`으로
  남깁니다 — 건너뛰면 신고를 거른 것인지 안 받아온 것인지 구분이 안 됩니다.

### 계수 검증 순위표

`CSV 내려받기` 옆 **`순위표 검증`** 버튼. 계수는 `그 값 ÷ 커트라인`인데
커트라인을 만든 전국 원본이 화면에 없어 확인할 길이 없었습니다.

날짜·시·도·기준을 고르면 그날 그 시·도를 줄 세운 결과가 나옵니다. 커트라인 줄에
색 선을 긋고 착한주유소를 강조해, 어디서 잘렸는지 눈으로 확인할 수 있습니다.

### 모바일

`720px` 아래에서만 다르게 그립니다. PC 화면은 손대지 않습니다.

지도와 목록은 본문에서 **보기만** 하고, 누르면 전체화면 시트가 열립니다.
지도는 손가락 끌기를 이동으로 먹어야 하고 페이지는 같은 동작으로 스크롤해야
하니, 한 화면에 같이 두면 둘 중 하나는 반드시 집니다.

목록은 카드로 바뀝니다 — 열 일곱 개짜리 표는 손바닥 화면에 들어가지 않습니다.

## 파이프라인

```
① normalize   stations.csv          → data/good-stations.json
② collect     오피넷 opDownload.do  → data/raw/{날짜}.json.gz
③ match       명단 ↔ 오피넷 코드    → data/station-mapping.json
④ aggregate   ②③ + 좌표 + 임계값    → client/public/data/latest.json
                                     → history.json · rank-{날짜}.json
⑤ push        판정 결과             → Supabase gs_daily (보관용)
```

`⓪ supabase:pull` 이 ① 앞에 붙어 명단·임계값·API 키를 내려받습니다.

**전부 GitHub Actions 가 돕니다.** Node 스크립트와 Playwright 만 쓰고 LLM 호출은
없습니다.

### 수집 주기

| 시각 (KST) | 잡히는 날짜 |
|---|---|
| 10:20 | 대개 전일분 |
| 19:30 | 대개 당일분 |

`collect` 는 **어제~오늘을 기간 조회로 한 번에** 받아 그중 다 올라온 가장 최근
날짜를 씁니다. 오피넷은 당일분을 하루에 걸쳐 채우는데(9/5 17시에 이미 10,223건,
전날 10,237건), '어제'만 받으면 현황판이 늘 하루 뒤처집니다. 오늘 치가 전날
건수의 80%에 못 미치면 아직 올라오는 중으로 보고 물러섭니다.

### 명단은 오피넷 코드를 들고 온다

`stations.csv` 의 `번호` 열이 오피넷 주유소코드입니다. 상호·주소로 추정하던
매칭이 사실상 필요 없어져 **472/472 전건**이 확정됩니다.

시·도·시·군·구는 `지역` 열이 아니라 **주소**에서 뽑습니다. 지역 열은 시·군·구까지만
적혀 있어 일반구를 잃습니다 — 그것만 믿었더니 포항·천안·창원 등 8개 시의 56곳이
구 없이 남아, 지도에서 그 시로 내려가면 아무것도 안 뜨는 상태가 됐습니다.

### 원본은 보관한다

안 남겼더니 판정식을 바꿀 때마다 두 달치를 다시 긁느라 세 시간씩 썼습니다.

```
원본 3.5MB → gzip 317KB (8.7%) → 연 113MB
```

`data/raw/*.json.gz` 를 커밋합니다. 압축 안 한 `.json` 만 gitignore 로 막아
3.5MB 짜리가 실수로 들어가지 않게 합니다. `backfill` 은 보관분을 먼저 보고,
있으면 내려받지 않고 바로 재계산합니다.

## 명령

```bash
npm run dev            # 개발 서버 (5173)
npm run check          # 타입 검사
npm run build          # 정적 빌드 → dist/

npm run normalize      # stations.csv → 명단
npm run collect        # 오피넷 수집 (어제~오늘)
npm run match          # 오피넷 코드 매칭
npm run aggregate      # 판정 · 시계열 · 순위표
npm run ranks          # 보관 원본으로 순위표만 다시
npm run backfill       # 과거 시계열 — 원본이 있으면 재계산, 없으면 내려받기
npm run coords:vworld  # 좌표 (국내에서만 — 해외 IP 는 막힌다)
```

### 배포

```bash
gh workflow run collect.yml                       # 수집부터 전부
gh workflow run collect.yml -f skip_collect=true  # 커밋된 데이터로 배포만 (~1분)
```

코드만 바꿨을 때는 `skip_collect` 를 쓰세요. NetFunnel 대기열이 길면 20분 넘게
잡힙니다.

## 알아둘 것

**오피넷 기간 조회는 3일이 한계입니다.** 7일치는 10분을 기다려도 파일이
떨어지지 않습니다. 3일치(30,714행·4MB)는 정상입니다.

**브이월드 지오코더는 GitHub 러너에서 막힙니다.** 미국 IP 에서 호출하면 전건
실패합니다. 국내에서 한 번 채워 커밋하면 그 파일을 계속 씁니다.

**`supabase:pull` 이 명단을 덮어씁니다.** 저장소 명단만 바꾸고 Supabase 를
갱신하지 않으면 다음 수집에서 옛 명단으로 되돌아갑니다. 지금은 폴(상표) 정보
유무로 판별해 막고 있습니다.

**데이터 파일은 `cache: "no-cache"` 로 받습니다.** GitHub Pages 가
`max-age=600` 을 붙여, 배포 직후 10분간 새 코드가 옛 데이터를 읽는 구간이
생겼습니다. 파일 이름에 `?v=` 를 붙이는 것만으로는 부족했습니다 — 그 값이 번들
안에 박혀 있어 `index.html` 이 캐시돼 있으면 옛 값을 씁니다.

**Supabase 는 RLS 를 켜고 정책을 하나도 만들지 않았습니다.** anon 키로는
테이블을 읽지도 쓰지도 못하고, 모든 접근이 `SECURITY DEFINER` 함수를 거칩니다.
접근코드와 API 키가 브라우저로 내려오지 않습니다.

더 자세한 배경과 남은 일은 [HANDOVER.md](HANDOVER.md) 에 있습니다.
