# 착한주유소 현황판

한국석유관리원 착한주유소 449곳이 **자기 지역 시세보다 싸게 팔고 있는지**를 신호등으로 보여주는 정적 현황판.

## 지도

전국 시·도 → 시·군·구 → 일반구 → **상세**, 네 단계로 내려간다.

- **지역마다 신호등 개수 배지**가 붙는다 (🟢 저렴 / 🟡 보통 / 🔴 비쌈).
- **착한주유소가 없는 지역은 그리지 않는다.** 경북은 23개 시군 중 9곳만 뜬다. 대신 상위 행정구역 외곽선을 옅게 남겨 위치를 가늠할 수 있게 했다.
- **휠로 확대, 끌어서 이동**할 수 있다 (최대 16배). 단계를 옮기면 초기화된다.
- 일반구 단계는 구를 둔 시에만 있다. 경북처럼 일반구가 없으면 시·군·구가 마지막 단계다.
- **상세 단계에서는 실제 지도 타일 위에 주유소 핀**이 찍힌다. 핀과 이름표는 그 주유소의 신호등 색을 그대로 쓴다. 전국에 449개를 한꺼번에 찍으면 알아볼 수 없으므로 더 내려갈 곳이 없는 지역(구, 또는 구가 없는 시·군)을 골랐을 때만 켜진다.

배지 위치는 무게중심이 아니라 **최대내접원 중심**(pole of inaccessibility)에서 잡는다. 경기도는 서울을 둘러싸고 있어 무게중심이 서울 위에 얹히고(실측 20px), 그대로 두면 두 배지가 겹친다. 그다음 배지끼리 서로 밀어내고, 밀려난 배지에는 지시선을 긋는다. 덕분에 서울·대전·대구·울산처럼 폴리곤이 작은 광역시도 개수가 빠지지 않는다.

## 신호등 판정

시·군·구 안의 **모든** 주유소 가격으로 평균 μ와 표준편차 σ를 구한 뒤, 착한주유소의 z점수로 색을 정한다.

```
z = (해당 주유소 가격 − 시군구 평균) / 시군구 표준편차

🟢 초록   z ≤ −0.5        지역 평균보다 유의미하게 저렴
🟡 노랑   −0.5 < z ≤ +0.5  평균 수준
🔴 빨강   z > +0.5         지역 평균보다 비쌈
```

착한주유소 449곳만으로는 지역 가격 분포를 알 수 없다. 그래서 **전국 약 1만 개 주유소 가격을 매일 통째로 받아** 시·군·구별 분포를 만든 뒤, 그 안에서 착한주유소의 위치를 잰다.

**표본 부족 처리** — 관내 주유소가 5곳 미만인 시·군·구는 σ가 하루 단위로 크게 흔들려, 가격이 그대로인데 색만 매일 바뀐다. 이런 지역은 **시·도 σ로 대체**하고 화면에 `표본부족` 배지를 단다. 평균은 대체하지 않고 언제나 그 지역의 실제 평균을 쓴다 — "우리 동네 평균가"는 그 동네 값이어야 담당자가 납득한다.

임계값과 최소 표본 수는 [`src/lib/signal.ts`](src/lib/signal.ts)의 `Z_GREEN` / `Z_RED` / `MIN_SAMPLE`.

## 빠른 시작

```bash
npm install
npx playwright install chromium
```

```bash
npm run normalize   # 1. adress.csv 정규화        → data/good-stations.json
npm run collect     # 2. 오피넷 전국 가격 수집     → data/raw/{날짜}.json
npm run match       # 3. 449곳 ↔ 주유소코드 매칭   → data/station-mapping.json
npm run geo         # 4. 행정구역 경계 생성 (최초 1회)
npm run aggregate   # 5. 신호등 판정               → client/public/data/latest.json
npm run dev         # 6. http://localhost:5173
```

`normalize`와 `geo`는 명단이나 경계가 바뀔 때만 다시 돌리면 된다. 일상 갱신은 `collect → aggregate`.

## 매칭

명단에는 상호+주소만 있고 가격 데이터는 오피넷 주유소코드 기준이다. 둘을 붙이는 것이 이 프로젝트에서 가장 손이 많이 가는 부분이다.

**상호로 매칭하면 반드시 깨진다.** 명단에 `행복주유소`가 4건, `대원주유소`·`명진주유소`·`삼양주유소` 등 동일 상호가 여러 지역에 흩어져 있다. 그래서 도로명주소를 1순위로 두고 상호는 같은 지역 안에서만 보조로 쓴다.

| 순위 | 방법 | 조건 |
|---|---|---|
| 1 | `manual` | `data/manual-mapping.json` 에 사람이 적어둔 값 |
| 2 | `address` | 같은 시·군·구 + 도로명 + 건물번호 |
| 3 | `address-sido` | 시·도 + 도로명 + 건물번호 — 시·군·구 개편 구제 |
| 4 | `name-exact` | 같은 시·군·구 + 상호 완전 일치 (후보 1개) |
| 5 | `name-fuzzy` | 같은 시·군·구 + 상호 유사도 0.82 이상 |
| 6 | `name-sido` | 같은 시·도 + 상호 완전 일치 (후보 1개) |

후보가 둘 이상이면 자동 확정하지 않는다. 틀린 주유소에 신호등을 달면 안 다느니만 못하다. 애매한 건은 전부 `data/match-report.md`로 넘어간다.

**미매칭을 손으로 채우려면** `data/match-report.md`를 보고 `data/manual-mapping.json`에 적는다.

```json
{ "145": "A0033752" }
```

키는 명단 순번(`seq`), 값은 오피넷 주유소코드. 다음 `npm run match`부터 최우선으로 반영된다.

## 행정구역

가격 데이터(오피넷)와 명단(`adress.csv`)의 행정구역 표기가 서로 다르고, 둘 다 최신 개편을 완전히 반영하지 못한다. `src/lib/region.ts`가 양쪽을 같은 키로 모은다.

- **광주광역시 + 전라남도 → 전남광주통합특별시.** 오피넷은 `전남광주`로 내려오고, 명단은 대부분 옛 이름(`광주 북구`, `전남 진도군`)으로 적혀 있다. 셋을 한 키로 모은다.
- **인천 서구 → 검단구 + 서해구**, **중구·동구 → 제물포구 + 영종구**. 명단은 아직 옛 이름이라 `address-sido` 단계에서 구제한다.
- **경북 군위군 → 대구 군위군** (2023년 편입).
- **일반구를 둔 시 13곳**(수원·성남·창원·청주 등)은 **시 레벨로 집계**한다. 구별로 쪼개면 σ 표본이 10개 안팎으로 떨어져 불안정해진다. 지도의 구 단계는 표시 전용이며, 신호등 판정은 시 단위 분포로 한다.
  - 오피넷은 시 단위까지만 주므로 구 정보는 명단 주소에서 가져온다. 명단의 시와 오피넷의 시가 일치할 때만 신뢰한다.
  - **부천시·화성시는 구 단계가 없다.** 2018년 경계 원본에 단일 폴리곤으로 들어 있어 구를 나눌 수 없다(부천 구 복원 2024, 화성 만세구 신설). 두 곳은 시 단위에서 멈춘다.

경계 원본은 kostat 2018년 기준이라 신설된 구의 경계가 없다. 지어낸 경계를 그리는 대신 **모체 폴리곤 하나에 여러 현행 구를 묶어** 칠하고, 상세 표에는 개별 구를 나눠 보여준다. 자세한 대응은 `data/geo-crosswalk-report.md`.

## 좌표

지도 핀을 찍으려면 주유소별 위경도가 필요한데, 이게 이 프로젝트에서 유일하게 API 키 없이는 온전히 풀리지 않는 부분이다.

**오피넷 다운로드 CSV에는 좌표가 없다.** 컬럼이 `번호, 지역, 상호, 주소, 기간, 상표, 셀프여부, 고급휘발유, 휘발유, 경유, 실내등유` 뿐이다.

| 방법 | 키 | 결과 |
|---|---|---|
| 오피넷 `detailById.do` (`npm run coords`) | 필요 | **446곳 전량, 정확** |
| OpenStreetMap Overpass (`npm run coords:osm`) | 불필요 | 65곳 (14.6%) |
| Nominatim 지오코딩 | 불필요 | **쓸 수 없음** |

Nominatim은 한국 도로명주소를 거의 못 찾는다. 실측하면 서울 강남 주소가 대구로, 포항 주소가 서울로 나온다. 채택하지 않았다.

OSM 방식은 두 조건을 모두 만족할 때만 좌표를 채운다. (1) 그 좌표가 해당 시·군·구 폴리곤 안에 있을 것, (2) 그 지역 안에서 상호가 사실상 같을 것. 처음엔 유사도 기준을 0.6으로 뒀는데 `(주)서해에너지`가 `SK 주유소`에, `동춘천농협주유소`가 (명단에 따로 있는) `춘천농협주유소`에 붙었다. 한국 주유소 상호는 "…주유소", "…에너지", "…농협" 처럼 어미가 겹쳐 편집거리가 실제보다 가깝게 나온다. 기준을 0.92로 올려 65곳만 남겼다. **틀린 핀보다 없는 핀이 낫다.**

붙은 짝은 `data/coords-report.md`에 전부 남는다. 잘못된 건은 `data/station-coords.json`에서 지우면 핀이 사라진다.

`OPINET_API_KEY`를 등록하면 `npm run coords`가 전량을 정확한 값으로 덮어쓰고, GitHub Actions에도 시크릿으로 넣어두면 매일 자동으로 갱신된다.

## 배경 지도

상세 단계에만 배경 타일을 깐다. 기본값은 **OpenStreetMap 표준 타일**로 키가 필요 없고 지명이 한글로 나온다.

다른 무료 후보도 확인했다. CARTO(`basemaps.cartocdn.com`)는 HTTP 200에 PNG를 돌려주지만 이미지에 `API KEY REQUIRED` 워터마크가 찍혀 있고 지명이 로마자다.

OSM 표준 타일은 OSMF 사용정책상 **가벼운 사용**을 전제로 한다. 접속이 늘면 브이월드(국토교통부, 무료 키·한글 표기)로 옮기는 것이 맞다. `.env` 또는 저장소 시크릿에 넣으면 코드 수정 없이 교체된다.

```
VITE_TILE_URL=https://api.vworld.kr/req/wmts/1.0.0/{키}/Base/{z}/{y}/{x}.png
VITE_TILE_ATTRIBUTION=국토교통부 브이월드
```

타일은 지도 라이브러리 없이 그린다. 웹 지도 타일이 Web Mercator이고 이 프로젝트도 `geoMercator`를 쓰므로, 타일 모서리를 같은 투영으로 변환하면 축에 나란한 사각형이 된다. 그 자리에 `<image>`를 놓기만 하면 된다.

## Supabase — 명단 관리와 로그인

착한주유소 명단은 이제 `adress.csv` 가 아니라 Supabase 가 원본이다. 관리 화면에서 고치면 다음 수집 때 반영된다.

**접근 모델은 계정 없이 접근코드 하나**다(기본 `kpetro`). 관리 화면은 `#/admin`.

```
현황판  https://joongyu01.github.io/good-station-board/
관리    https://joongyu01.github.io/good-station-board/#/admin
```

### 왜 anon 키를 공개해도 되는가

모든 테이블에 RLS 를 켜되 **정책을 하나도 만들지 않았다.** 그래서 anon 키로는 테이블을 읽지도 쓰지도 못하고, 모든 접근이 `SECURITY DEFINER` 함수를 지나야 한다. 접근코드도 함수 안에서 대조하므로 브라우저로 내려오지 않는다.

실제로 확인한 결과다.

| 시도 | 결과 |
|---|---|
| 네 테이블 직접 읽기 | 전부 `[]` |
| `gs_config` PATCH 로 접근코드 변조 | 204 를 받지만 실제 0행. `kpetro` 그대로 |
| `gs_station` 직접 insert | 반영 안 됨 |

`gs_config` PATCH 가 204 를 주는 건 PostgREST 가 "영향받은 행 없음"에도 204 를 돌려주기 때문이다. 로그인으로 확정했다.

### API 키는 화면으로 내려보내지 않는다

`gs_secret` 에 넣은 값은 관리 화면에 **이름·설정여부·앞뒤 4자만** 보인다. 실제 값은 수집 작업이 `service_role` 로 직접 읽는다. 접근코드 하나로 들어오는 구조라, 코드가 새더라도 API 키까지 함께 새면 안 되기 때문이다.

오피넷 키는 관리 화면 → **API 키** 탭에서 `OPINET_API_KEY` 로 등록하면 된다. 등록하면 다음 실행부터 주유소 좌표가 446곳 전량으로 채워진다.

### 설치

1. Supabase → SQL Editor 에 [`supabase/schema.sql`](supabase/schema.sql) 전체를 붙여넣고 Run (멱등, 두 번 실행해도 안전)
2. `client/public/config.js` 에 Project URL 과 anon public 키 입력
3. 명단 이관: `SUPABASE_URL=... SUPABASE_ANON_KEY=... npm run supabase:seed`
4. GitHub 저장소에 등록
   - 변수 `SUPABASE_URL` (공개값)
   - 시크릿 `SUPABASE_SERVICE_ROLE_KEY`

### 테이블

| 테이블 | 내용 |
|---|---|
| `gs_config` | 접근코드, 신호등 임계값 |
| `gs_secret` | 외부 API 키 (값은 화면에 안 나옴) |
| `gs_station` | 착한주유소 명단 |
| `gs_daily` | 일별 판정 결과 — **449곳 × 4유종만** |
| `gs_session` | 세션 |

`gs_daily` 에 전국 1만 건을 매일 넣으면 연 370만 행이라 무료 한도(500MB)를 넘는다. 그래서 착한주유소 것만 넣고(하루 1,796행) 전국 원본은 수집 작업 안에서만 쓰고 버린다.

| `npm run supabase:seed` | 기존 명단 449곳을 Supabase 로 이관 |
| `npm run supabase:pull` | 명단·임계값·오피넷 키를 내려받아 파일로 떨어뜨린다 |
| `npm run supabase:push` | 일별 판정 결과를 `gs_daily` 에 적재 (service_role 필요) |

`supabase:pull` 은 `service_role` 이 있으면 테이블을 직접 읽고, `anon` 키 + 접근코드만 있으면 관리 화면과 같은 RPC 로 읽는다. `service_role` 을 로컬에 내려놓지 않고도 읽기를 확인할 수 있게 두 갈래를 뒀다.

**Supabase 가 없거나 접속이 안 되면 아무것도 덮어쓰지 않고 넘어간다.** 저장소에 커밋된 기존 파일로 파이프라인이 계속 돌아야 하기 때문이다.

## 자동 갱신

`.github/workflows/collect.yml` 이 매일 10:20 KST에 돌아간다.

```
Supabase pull → 수집 → 매칭 → 좌표 보강 → 집계 → Supabase push → 커밋 → Pages 배포
```

오피넷 다운로드 페이지는 **NetFunnel 대기열**을 통과해야 해서 간헐적으로 실패한다. 이는 정상 범주로 보고, 수집 단계는 `continue-on-error`로 두었다. 실패하면 커밋을 건너뛰고 **직전 데이터로 현황판이 그대로 뜬다.** 수집기 자체도 3회 재시도한다.

GitHub Pages를 쓰려면 저장소 Settings → Pages → Source를 **GitHub Actions**로 설정한다.

## 알려진 제약

- **미매칭 3곳** — `두암주유소`(전남광주 북구), `회천주유소`(전남광주 보성군), `대황주유소`(충북 제천시). 앞뒤 두 곳은 오피넷 전국 목록에 해당 상호가 없다(폐업 또는 가격 미신고로 추정). `회천주유소`는 후보 `회천농협주유소`가 같은 도로에 있으나 상호와 건물번호(2333 vs 2383)가 모두 달라 자동 확정하지 않았다. 확인 후 `manual-mapping.json`에 적으면 된다.
- **경계 데이터가 2018년 기준.** 최신 경계를 확보하면 `data/geo/municipalities-raw.json`을 교체하고 `scripts/build-geo.ts`의 `CROSSWALK`를 비우면 된다.
- **좌표가 449곳 중 56곳만 있다.** 지도 핀은 좌표가 있는 곳만 찍힌다. 나머지는 지도에 안 보일 뿐 목록·신호등에는 그대로 나오고, 상세 화면이 몇 곳이 빠졌는지 알려준다.
  - 전량을 정확히 채우려면 **오피넷 OpenAPI 키**가 필요하다. 키를 `OPINET_API_KEY` 로 넣고 `npm run coords` 를 돌리면 `detailById.do` 가 주유소별 좌표를 정확히 준다.
  - 키가 없을 때의 차선책이 `npm run coords:osm` 이다. OpenStreetMap에 등록된 주유소와 **상호 일치 + 해당 시·군·구 폴리곤 내부** 두 조건을 모두 만족할 때만 채택한다. 현재 56곳이 이 경로로 채워졌고, 60곳은 이름은 같지만 다른 지역이라 기각되었다.
  - Nominatim 지오코딩은 쓰지 않는다. 한국 도로명주소를 거의 못 찾는다 — 실측으로 서울 강남 주소가 대구로, 포항 주소가 서울로 나왔다.
- **이력 30일.** 일별 스냅샷은 최근 30일만 보관한다(`scripts/aggregate.ts`의 `KEEP_DAYS`). 장기 추이가 필요하면 별도 저장소나 DB로 빼는 편이 낫다.
